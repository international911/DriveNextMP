# Каталог автомобилей, поиск и профиль

Основа: страницы 80–86 методички «Разработка мобильных приложений».

## Подготовка Supabase

После `supabase/setup.sql` выполните `supabase/catalog.sql` в SQL Editor своего проекта Supabase. Скрипт создаёт таблицу `cars`, включает RLS, разрешает чтение доступных машин вошедшим пользователям и добавляет две демонстрационные записи. В приложение добавляется только URL проекта и publishable key из `local.properties`; SQL Editor работает через панель Supabase.

## Что реализовано

- Главная: `RecyclerView` с карточками автомобилей, получение списка из Supabase, загрузка, сообщение об ошибке и повторный запрос.
- Поиск: `SearchView`, запрос по марке или модели после изменения текста, экран результатов, повторная загрузка, сохранение запроса между запусками.
- Нижняя навигация: главная и настройки.
- Настройки: профиль пользователя, переход в профиль, пункты меню.
- Профиль: имя и почта из Supabase, текущий аватар из закрытого Storage, выбор нового фото, загрузка и сохранение пути в таблице `profiles`, выход с очисткой сессии и стека экранов.
- Кнопка «Забронировать» открывает экран «Оформление аренды» с выбранным автомобилем. На текущем этапе экран не создаёт бронь.

## Проверка вручную

1. Выполнить SQL-скрипт и войти в приложение.
2. Убедиться, что отображаются Toyota Camry и Kia Rio; нажать «Детали» и «Забронировать».
3. Найти `Toyota`, затем строку без совпадений; перезапустить приложение с непустым запросом.
4. В Supabase временно отключить сеть устройства: проверить сообщение об ошибке и кнопку «Повторить» после восстановления связи.
5. Открыть настройки и профиль, выбрать новый аватар, вернуться в профиль и проверить его отображение.
6. Выйти и убедиться, что кнопка «Назад» не открывает защищённый экран.

Сборка проверена командой `gradlew.bat :app:assembleDebug --offline`. Скрипт SQL выполнен пользователем в панели Supabase; результаты проверки приложения на эмуляторе приведены ниже.

## Результаты проверки поиска и загрузки

Проверено на `Medium_Phone_API_37.0` после выполнения `catalog.sql` в Supabase:

- `Toyota` показывает Toyota Camry; замена запроса на `Kia` на экране результатов показывает Kia Rio.
- `zzzx` показывает «Автомобили не найдены».
- После принудительного закрытия и нового запуска приложения запрос `zzzx` и пустой результат восстанавливаются.
- Без сети поиск показывает «Не удалось выполнить поиск. Попробуйте снова.» и кнопку «Повторить». После восстановления сети повторная попытка возвращает Toyota Camry.
- Без сети главная показывает «Не удалось загрузить данные. Попробуйте снова.» и кнопку «Повторить». После восстановления сети повторная попытка возвращает Toyota Camry и Kia Rio.

## Профиль, фото машин и переходы

- В карточках Toyota Camry и Kia Rio используются фотографии, предоставленные пользователем; другие модели показывают стандартный значок.
- Проверена повторная загрузка тестового аватара в закрытый Supabase Storage и его отображение после перезапуска приложения. В профиле сохранены имя, почта и пол.
- Проверен выход: открывается экран входа, кнопка «Назад» выводит на домашний экран Android, а новый запуск приложения не открывает список машин без входа.
- «Детали» показывают фото, название, цену и характеристики выбранного автомобиля. Из них и из карточки можно открыть «Оформление аренды»; возврат из аренды в детали работает.
- Экран «Оформление аренды» показывает выбранный автомобиль и цену, без выбора дат и сохранения брони.
- Пункты «Мои бронирования» и «Подключить свой автомобиль» открывают соответствующие разделы. Действия внутри этих разделов будут добавлены позже.
