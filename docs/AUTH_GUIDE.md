# Вход и регистрация DriveNext

Пояснения к методам оставлены в самих Kotlin-файлах. Общая карта проекта находится в [README](README.md).

## Что сделано

На стартовом экране есть выбор входа и регистрации. Вход проверяет почту и пароль, умеет показывать пароль, отправлять запрос на восстановление и открывать Google OAuth. Регистрация разделена на три шага: учётные данные, личные данные, документы. Есть выбор даты, фото из галереи и снимок камерой. После успешной регистрации появляется экран поздравления, затем главный экран. Данные форм при переходе назад сохраняются в `AuthViewModel`.

Запросы входа и регистрации идут в Supabase Auth. Фото отправляются в **закрытый** Storage bucket, профиль — в таблицу `profiles`. Сессия хранится зашифрованной ключом Android Keystore. Если Supabase ещё не настроен, приложение показывает ошибку настройки и не делает вид, что пользователь вошёл.

## Как подключить Supabase

1. Создать проект в [Supabase Dashboard](https://supabase.com/dashboard) и дождаться его запуска.
2. Открыть **Connect** в проекте: там показаны Project URL и publishable key. Ключ также доступен в **Settings → API Keys**.
3. В **SQL Editor** один раз выполнить [`supabase/setup.sql`](../supabase/setup.sql). Скрипт создаёт таблицу и закрытое хранилище с правилами доступа владельца. При выключенной опции **Automatically expose new tables** скрипт явно выдаёт доступ к `profiles` только вошедшим пользователям.
4. В `local.properties` добавить:

   ```properties
   supabase.url=https://PROJECT_REF.supabase.co
   supabase.publishableKey=sb_publishable_...
   ```

   Вместо нового publishable key можно использовать старый `anon` key. Нужен только **публичный** ключ. `service_role` в мобильное приложение добавлять нельзя.
5. Для немедленной загрузки профиля и фото после регистрации в **Authentication → Sign In / Providers → Email** временно выключить **Confirm Email**. Если оно включено, Supabase создаст аккаунт без сессии: приложение честно сообщит, что нужно подтвердить адрес, но завершить загрузку документов в этой версии не сможет. Для реального приложения подтверждение почты следует включить и доработать продолжение регистрации после подтверждения.
6. Для Google входа включить Google provider в Supabase, настроить OAuth credentials в Google Cloud и добавить `com.example.drivenext://auth-callback**` в **Authentication → URL Configuration → Redirect URLs**. Шаблон включает параметр `state`, который приложение добавляет к адресу возврата. Google сначала возвращает пользователя в Supabase callback, затем Supabase открывает deep link приложения.
7. Сделать Gradle Sync и пересобрать приложение. Публичный ключ будет внутри APK, поэтому доступ к данным обязательно ограничен RLS в SQL.

Проект Supabase подключён. На момент проверки 18 ноября 2026 года его публичные настройки показывали `external.google=false`: Google Provider выключен, поэтому полный успешный вход через Google пока невозможно проверить. Приложение сообщает об этом при нажатии кнопки. После включения провайдера нужно пройти вход в браузере и убедиться, что возврат в приложение открывает главный экран.

Для регистрации используйте действующий адрес почты. Supabase отклоняет `example.com` и другие тестовые домены; приложение предупреждает об этом уже на первом шаге.

## Что проверено

- `:app:assembleDebug` — успешная сборка.
- На Android Emulator API 37: открытие регистрации, переходы 1 → 2 → 3, календарь, две фотографии через камеру и FileProvider, сохранение данных при возврате 3 → 2 → 1. Дополнительно проверен выбор фотографий через системную галерею.
- Отправка полностью заполненной формы без Supabase показывает ошибку настройки; ложного экрана успешной регистрации нет.
- С подключённым проектом Supabase проверен отказ при неверном логине. Реальную регистрацию с загрузкой документов и успешный Google OAuth нужно проверить после настройки соответствующих серверных параметров.

Дополнительная проверка 18 ноября 2026 года:

- 27 проверок валидатора прошли: почта, пароли и повтор пароля, согласие, русские имена, обязательные поля, даты, номер прав и фотографии.
- На эмуляторе проверены сообщения для неверной почты, короткого пароля, отсутствующего согласия, неверного номера прав и отсутствующих фото. Ошибка сервера `invalid_credentials` теперь отображается как «Неверная почта или пароль».
- На третьем шаге проверены область аватара, выбор фотографии и показ превью, выбор двух документов, возврат ко второму шагу с сохранением введённых данных.
- Для Google проверены запуск по нажатию, понятная ошибка при выключенном провайдере и обработка отмены в обратной ссылке. Успешный обмен кода на сессию и открытие главного экрана требуют включённого Google Provider и реального входа в Google.
- В публичных настройках Supabase также указано `mailer_autoconfirm=false`. Подтверждение почты включено; немедленная загрузка документов после регистрации требует настройки из пункта 5 либо отдельного сценария продолжения регистрации после подтверждения.

## Где что находится — простыми словами

| Файл | Зачем он нужен |
| --- | --- |
| `screen_entry.xml`, `screen_auth.xml`, `screen_catalog.xml` | Графическая вёрстка стартового экрана, форм и каталога автомобилей. |
| `AuthActivity.kt` | Показывает нужный шаг, читает поля, открывает календарь/галерею/камеру, выводит ошибки и переключает экраны. |
| `AuthViewModel.kt` | Помнит введённые данные при повороте телефона и выполняет сетевые операции в отдельном потоке. |
| `RegistrationDraft.kt` | Временный набор введённых данных регистрации. |
| `AuthValidator.kt` | Проверяет почту, пароли, даты, номер удостоверения и наличие обязательных фото. |
| `AuthRepository.kt` | Отправляет HTTP запросы в Supabase Auth, Storage и таблицу `profiles`. |
| `SecureSessionStore.kt` | Шифрует и сохраняет токены, чтобы не вводить пароль при каждом запуске. |
| `MainActivity.kt`, `StartupViewModel.kt` | Управляют запуском приложения, экраном выбора входа и переходом на главную. |
| `AndroidManifest.xml`, `file_paths.xml` | Регистрируют экран авторизации, возврат из браузера и безопасный адрес фото камеры. |
| `supabase/setup.sql` | Создаёт серверные таблицу, закрытое хранилище и правила доступа. |

## Основные методы для защиты

- `render()` в `AuthActivity` берёт текущий шаг из ViewModel и показывает нужные секции XML.
- `syncFields()` переносит текст из полей в `RegistrationDraft` перед переходом или поворотом.
- `primaryAction()` проверяет текущий шаг и либо показывает ошибку, либо идёт дальше/вызывает сервер.
- `chooseDate()` открывает `MaterialDatePicker`, получает выбранную дату как UTC-миллисекунды и форматирует её. Дата рождения: `MM/DD/YYYY`, выдача прав: `DD/MM/YYYY` — именно так сказано в текстовых требованиях методички.
- `choosePhoto()` предлагает галерею или камеру. `savePhoto()` сохраняет полученный `Uri` в черновике.
- `login()`, `register()`, `resetPassword()` в ViewModel запускают операции в отдельном потоке; `AuthRepository` выполняет реальные HTTP запросы.
- `validLocalSession()` проверяет, есть ли ещё действующий токен; `clearSession()` удаляет его при выходе.

Теперь календарь соответствует методичке: используется `MaterialDatePicker` из Material Components. Выбор ограничен датами от 1900 года до текущего дня; перевод UTC-миллисекунд в `LocalDate` выполняется в зоне UTC, чтобы дата не смещалась из-за часового пояса.

## Ответы на контрольные вопросы методички

1. **MaterialDatePicker** — календарный диалог из Material Components. Он позволяет выбрать дату в оформлении Material Design.
2. Вызвать `MaterialDatePicker.Builder.datePicker()`, задать заголовок через `setTitleText()`, затем `build()`.
3. В `FragmentActivity` вызвать `picker.show(supportFragmentManager, "datePicker")`. Для этого нужна библиотека Material Components.
4. `addOnPositiveButtonClickListener` получает выбранную дату после нажатия кнопки подтверждения.
5. `selectedDateUtcMillis` — выбранная дата как число миллисекунд от 1 января 1970 года в UTC; перед показом человеку её форматируют.
6. **Uri** — адрес ресурса, например изображения в медиатеке. Пикер возвращает адрес, через который приложение читает фото, а не обязательно обычный путь к файлу.
7. **Activity Result API** запускает другое приложение или системный экран и возвращает результат. `registerForActivityResult` заранее регистрирует обработчик этого результата с учётом жизненного цикла Activity.
8. `PickVisualMedia` открывает системный выбор медиа и возвращает `Uri` одного выбранного фото или `null`, если пользователь отменил выбор.
9. `TakePicture` передаёт камере подготовленный `Uri` и возвращает `true`, если снимок сохранён, или `false`, если нет.
10. **FileProvider** выдаёт камере временный безопасный `content://` адрес файла приложения. Так камера может записать снимок без раскрытия пути к файлу и небезопасного `file://` URI.
