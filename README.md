# Лабораторная работа № 1 — DriveNext

Подробный разбор проекта для защиты и ответы на контрольные вопросы: [PDF](DriveNext_Lab1_Defense_Guide.pdf). Исходная версия документа: [HTML](defense_guide.html).

Нативное Android-приложение на Kotlin по страницам 51–59 методических указаний.

## Что реализовано

1. Системный SplashScreen и фирменный экран загрузки с названием, слоганом и иллюстрацией. Через 2,5 секунды приложение переходит дальше.
2. Экран отсутствия интернета с повторной проверкой. Проверяется подтверждённый доступ в интернет (`NET_CAPABILITY_VALIDATED`). При восстановлении сети открывается прерванный экран.
3. Три страницы приветствия с перелистыванием, кнопками «Далее», «Пропустить», «Поехали» и индикатором текущей страницы. После завершения флаг сохраняется в `SharedPreferences`.
4. Экран назначения «Вход и регистрация». Авторизация и Supabase относятся к следующим лабораторным работам; здесь это точка перехода из сценария лабораторной № 1.

Изображения экранов взяты из приложенного PDF и обрезаны до отдельных иллюстраций. Исходные подписи и кнопки нарисованы нативными Android View, поэтому остаются читаемыми на разных экранах.

## Открытие и сборка

Откройте папку `D:\MP LAB` в Android Studio. Нужны Android SDK API 37, JDK 17+ и подключение к репозиториям Google Maven и Maven Central для первой синхронизации. Минимальная версия устройства — Android 12 (API 31).

В терминале проекта:

```powershell
.\gradlew.bat :app:assembleDebug
```

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`.

Снимки проверенного интерфейса: `screenshots/onboarding-portrait.png` и `screenshots/onboarding-landscape.png`.

## Проверка поведения

1. Удалите приложение или очистите его данные. Запустите с интернетом: экран загрузки длится около 2,5 секунд, затем открывается первый слайд.
2. Перелистните все три слайда. Проверьте, что «Далее» на последнем меняется на «Поехали» и открывает экран входа и регистрации.
3. Перезапустите приложение: после загрузки приветствие больше не показывается.
4. Очистите данные ещё раз, запустите и нажмите «Пропустить»: следующий запуск также должен пропустить приветствие.
5. Выключите интернет до запуска: после загрузки откроется экран ошибки. «Повторить попытку» без сети оставляет экран на месте; после восстановления сети возвращает на первый слайд или экран входа.
6. Выключите интернет во время второго слайда: после восстановления сети должен открыться второй слайд.
7. Поверните устройство на экране приветствия: текущий слайд сохраняется. Проверьте небольшой и большой экран.

Сборка `:app:assembleDebug` выполнена успешно 3 ноября 2026 года. На эмуляторе API 37 проверены первый запуск, все три слайда, «Пропустить», «Поехали», повторный запуск, запуск без сети, повторная попытка, восстановление сети, сохранение второго слайда после перебоя сети и поворота. Портретный и горизонтальный экраны проверены визуально. Android Lint здесь не запустился офлайн, поскольку его артефакт отсутствует в локальном кэше.

## Ответы на контрольные вопросы

1. Переменную в Kotlin объявляют через `val` (только чтение) или `var` (можно менять), например `val page = 1`.
2. `Activity` — компонент Android, представляющий экран и управляющий его жизненным циклом.
3. `Intent` описывает действие или переход и позволяет запустить другую Activity или системную функцию.
4. SplashScreen показывает единый стартовый экран и скрывает краткую загрузку, избегая пустого экрана и резкой смены интерфейса.
5. Тема `Theme.SplashScreen` задаётся в ресурсах и указывается для стартовой Activity в `AndroidManifest.xml`.
6. `installSplashScreen()` вызывается до `super.onCreate()` и до создания интерфейса, чтобы стартовая тема применялась с самого начала.
7. Разрешения объявляются тегами `<uses-permission>` в `AndroidManifest.xml`. Без необходимого разрешения сетевой запрос или проверка состояния сети не будут доступны приложению.
8. `INTERNET` нужен для сетевых запросов; `ACCESS_NETWORK_STATE` — для чтения состояния сети через `ConnectivityManager`.
9. `AndroidManifest.xml` описывает приложение для системы: компоненты, точку запуска, разрешения и темы.
10. `Fragment` — часть интерфейса со своим жизненным циклом внутри Activity. Activity может существовать как самостоятельная точка входа; Fragment размещается в Activity или другом контейнере.
